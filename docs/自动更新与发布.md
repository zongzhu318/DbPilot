# GitHub Actions 安装包与自动更新

应用内通过「工具 → 检查更新」检查新版；正式安装版本启用定时检查。
macOS 使用原生 Sparkle 2.10.0，Windows 使用 WinSparkle 0.9.4。
macOS 升级弹窗的更新说明内嵌在 appcast 中（`description` + `sparkle:format="markdown"`，由距上一个稳定版的提交汇总生成）；Windows 的更新说明链接到对应 GitHub Release 页面。
安装包均自包含 .NET 8，无需用户另装运行时。

## 开发版与正式版隔离

构建通道由 `DbPilot.csproj` 的 `BuildChannel` 控制：Debug 默认 `Development`，Release 默认 `Production`，也可通过 `-p:BuildChannel=Development` 显式指定。

- 开发版显示名为 `DbPilot Dev`，数据目录为 `DbPilot Dev`，与正式版 `DbPilot` 完全隔离。
- 开发版不执行 Sparkle / WinSparkle 检查更新，避免本地构建被正式更新源替换。
- macOS 开发版打包为独立的 `DbPilot Dev.app`（`com.dbpilot.dbpilot.dev`），只输出到 `artifacts/macos-dev/`；`--install` 安装到 `~/Applications`，不会触碰 `/Applications/DbPilot.app`。
- 正式发布流水线保持 Release/Production 配置，bundle id 仍为 `com.dbpilot.dbpilot`。

本地开发命令：

```sh
scripts/dev/run-macos.sh
scripts/dev/package-macos-dev.sh --install
```

不要用开发版构建覆盖 `/Applications` 中的正式应用；开发和调试优先使用 `DbPilot Dev.app` 或 `dotnet run`。

## 产物

在 GitHub **Actions → 发布 macOS / Windows 版本 → Run workflow** 手动触发。标签留空时自动取上一个稳定版补丁号 +1（首次发布回退 `DbPilot.csproj` 的版本号）；也可以填写尚未发布的全新标签（如 `v0.3.1`）。流水线先校验版本与更新签名密钥，再检查、打包、更新签名并发布 GitHub Release：

- `DbPilot-0.3.1-osx-arm64.dmg`：Apple Silicon，macOS 12 或更高。
- `DbPilot-0.3.1-osx-x64.dmg`：Intel，macOS 12 或更高。
- `DbPilot-0.3.1-win-x64-setup.exe`：Windows x64，按当前用户安装，无需管理员权限。
- `appcast-osx-arm64.xml`、`appcast-osx-x64.xml`、`appcast-win-x64.xml`。
- `SHA256SUMS.txt`：最终安装包与更新源的校验值。

每种架构订阅独立源，地址为 `https://OWNER.github.io/REPO/stable/appcast-RID.xml`，由流水线发布阶段部署到 GitHub Pages（需在仓库 Settings → Pages 将 Source 设为 GitHub Actions）。安装包本体仍托管在 GitHub Release 附件，更新源中的下载链接固定到版本对应的 release。
流水线在发布阶段于所选提交创建并推送 `v版本号` 标签。已有 release 不覆盖，请使用递增的新版本。
Linux 不走此安装器流程，仍可使用 `publish.ps1 -Runtime linux-x64` 生成程序。

## 一次性配置：更新签名（必需）

在可信 Mac 上下载 [Sparkle 官方发布包](https://github.com/sparkle-project/Sparkle/releases/tag/2.10.0)，解压后运行：

```sh
./bin/generate_keys
./bin/generate_keys -x /安全路径/sparkle-private-key
```

`generate_keys` 显示公钥并将私钥存入登录钥匙串；`-x` 导出用于 CI 的私钥。
公私钥需要永久保留和安全备份，后续版本使用同一对密钥。
Sparkle 2.10 新生成的私钥是 Base64 编码的 32 字节种子，旧版导出为 96 字节；流程兼容两种格式，不能把私钥末尾直接当成公钥。

在 GitHub 仓库 **Settings → Secrets and variables → Actions** 配置：

| 类型 | 名称 | 内容 |
| --- | --- | --- |
| Variable | `SPARKLE_PUBLIC_KEY` | 工具输出的 Base64 Ed25519 公钥（32 字节），不含 XML 标签 |
| Secret | `SPARKLE_PRIVATE_KEY` | 导出文件的完整文本内容，不要再 Base64 编码 |

macOS 和 Windows 使用同一对 Ed25519 密钥。私钥仅传入最后的签名任务，不写入安装包、日志或仓库。
更新源签名针对完成签名、公证后的最终安装文件生成。签名后不要改动安装文件。
未配置公钥或私钥，流程会失败，避免发布不能验证的升级。
公开 GitHub 仓库可直接使用；私有仓库的匿名下载不可用，需要另行部署公开 HTTPS 更新源。
GitHub Actions 必须允许 workflow 的 `contents: write` 权限以创建 Release。

## Apple Developer ID 签名与公证（正式分发建议配置）

将 **Developer ID Application** 证书和对应私钥从钥匙串导出为带密码的 `.p12`。
添加以下 repository secrets：

| 名称 | 内容 |
| --- | --- |
| `APPLE_CERTIFICATE_P12_BASE64` | `.p12` 文件的 Base64 内容 |
| `APPLE_CERTIFICATE_PASSWORD` | `.p12` 导出密码 |
| `APPLE_SIGNING_IDENTITY` | `Developer ID Application: 姓名或公司 (TEAMID)` |
| `APPLE_ID` | 用于公证的 Apple ID |
| `APPLE_TEAM_ID` | Apple Developer Team ID |
| `APPLE_APP_PASSWORD` | Apple ID 的应用专用密码 |

配置完整后，脚本签名嵌套二进制、Sparkle helper、框架及主应用，公证并 staple 应用和 DMG，再生成升级签名。
未配置时生成 ad-hoc 签名 DMG，可用于内部测试，但初次打开可能被 Gatekeeper 阻止。
Sparkle 的 Ed25519 更新签名和 Apple 的代码签名是两种用途不同的签名，都需要保留。
Windows EXE 已生成可安装卸载的 Inno Setup 安装器；当前未配置 Authenticode，首次下载可能显示 SmartScreen 提示。

## 发布

在 GitHub **Actions → 发布 macOS / Windows 版本 → Run workflow** 触发；标签留空自动递增，或填写全新标签（如 `v0.3.1`）。
流水线会自动创建标签、生成 Release 并部署更新源，无需手工 `git tag`。
首次使用应安装这一流程生成的 DMG / EXE；此前普通 ZIP 或开发版没有更新框架，不能自动迁入。
macOS 将应用拖到 `/Applications` 后运行，不要直接在 DMG 内使用。
先发布一个版本并安装，再发布更高版本，分别在 Intel/ARM Mac 与 Windows 上验证检测、下载、签名校验、安装和重启。
Windows 安装时若有未保存 SQL 或数据改动，WinSparkle 会阻止关闭；完成保存后重试安装。
macOS 安装更新时若有未保存内容，会等待保存、提交/撤销及任务结束后继续。
自动检测更新不等于强制退出；应用不会为更新主动放弃未保存的数据库编辑。

## 本地打包

Mac（需 .NET 8 SDK、Xcode Command Line Tools）：

```sh
export VERSION=0.3.1 RID=osx-arm64 REPOSITORY=OWNER/REPO PUBLIC_KEY='你的公钥'
bash scripts/release/package-macos.sh
```

Windows（需 .NET 8 SDK、Inno Setup 6，脚本会尝试通过 Chocolatey 安装 Inno Setup）：

```powershell
$env:VERSION = '0.3.1'
$env:REPOSITORY = 'OWNER/REPO'
$env:PUBLIC_KEY = '你的公钥'
./scripts/release/package-windows.ps1
```

本地输出在 `artifacts/installers/`。下载的 Sparkle 与 WinSparkle 版本在脚本中固定；升级框架时需同步检查 API、最低系统版本与签名工具。
